# Native nontrading integration gate

`native_integration.py` is a development-only harness. Its default `--action preflight` inspects the fixture, platform version resources/hashes and cached EURUSD history without launching MetaEditor or MT5. Explicit `--action execute` delegates to the existing profile, compiler, snapshot, tester, journal and report helpers. Run separately with PowerShell 7 and Windows PowerShell 5.1, using fresh short run roots and evidence directories.

Required absolute selectors are `--skill-root`, `--platform-root`, `--cache-root`, `--run-root`, `--powershell`, and `--output`; `--python` selects the existing shared Python. Supply verified genuine MT5 platform binaries. Only symbol caches and the selected EURUSD 2025 history/tick metadata are copied from the cache root. Accounts, credentials, configuration, profiles and existing EAs are excluded. The separate installation and its derived data identity must be unused. Installation-to-data identity uses the uppercase canonical path's UTF-16LE MD5, with genuine startup needed to establish the actual association. No saved-account fallback is provided.

The fixture contains five closed-interval boundaries and six independently specified state transitions. Settings are EURUSD/M1, January 12 to February 28, 2025, model 0, USD 100,000, leverage 100 and execution mode 0, with a fresh nonce preset. Compile with zero errors/warnings and a fresh receipt/snapshot. A changed header must fail the trusted prelaunch snapshot gate with exit 2; result JSON may be absent because this gate precedes output-directory creation. Restore the header and recompile before the accepted run. Native success requires the unique marker, eleven passed assertions, verified completion/cleanup, complete inspected journals, a hash-linked report and zero native trades/deals. Synthetic tests establish orchestration only. Missing history or incomplete execution fails the gate.

Retain failed native evidence. No global environment settings change; Windows PowerShell children receive their native module path. This harness, its tests and fixture inspections are excluded from portable runtime packages.

Optional `--demo-auth-file` selects a private absolute JSON file for a newly provisioned dedicated MetaQuotes-Demo account. Its object has exactly three string fields: `login`, `server`, and `password`; `server` must be `MetaQuotes-Demo`. Do not reuse an existing saved account or place credentials in repository files, command-line values or retained artifacts. Preflight only validates this private input; it does not launch or authenticate. Account provisioning is separate from this harness and requires the platform's account-registration interface.

Explicit execution compiles the development-only `NativeDemoProbe.mq5`, initializes only that selected account in the fresh terminal/data identity, and runs the probe as a script outside Strategy Tester. The probe requires a connected terminal, exact account/server identity and `ACCOUNT_TRADE_MODE_DEMO`; real, contest, unknown, mismatched or disconnected accounts fail. MQL5 tester execution is forbidden for this identity check. API definitions were verified through the installed CHM's account properties, terminal properties and MQL5 program properties. Startup configuration follows the official [platform startup documentation](https://www.metatrader5.com/en/terminal/help/start_advanced/start).

Temporary account configuration, expected-identity inputs and authentication copies live under restricted owner/SYSTEM ACLs outside retained artifacts. Process arguments contain only their paths. The account's local terminal data remains private and must not be archived as validation evidence. `Read-NativeBootstrapEvidence.ps1` reuses the production redactor and retains hashes plus bounded sanitized excerpts; console text cannot supply the required native journal marker. Known temporary plaintext is removed only after owned-process cleanup is verified. Cleanup uncertainty retains protected private evidence and blocks further execution. The subsequent tester workflow preserves the existing preset, profile and report interfaces and the eleven-assertion fixture. Simulated tester account properties do not substitute for this native bootstrap check.

The probe permits up to three minutes for first-start connectivity, within the selected process deadline. Genuine build 6253 returned native exit 3 when `StartUp/ShutdownTerminal=1` closed the script terminal. Bootstrap accepts native exit 0 or that configured shutdown result only after the exact account marker and verified cleanup; the original exit is retained. Failed account probes still fail even with exit 3. The subsequent Strategy Tester completion continues to require exit 0. Sanitized bootstrap journals are collected after verified cleanup even when the process or account probe failed.

MT5 treats `/config` inputs as read-only, so a successful bootstrap does not itself persist the default account selection. After verified native identity and shutdown, the harness selects that demo login/server in the private terminal's default `config/common.ini`, preserving other Common settings. It requires the terminal-created account database and writes no plaintext password; credentials remain in the terminal's encrypted account storage. This private state stays outside retained validation artifacts. The tester receives its existing separate configuration unchanged.

The production journal reader masks complete application markers. MT5 also echoes the `TestNonce` input independently. The harness preserves the original journal-reader result and writes `native-journal.json` with that nonce masked in observation strings. It records both artifact hashes and keeps segment/source commitments and counts unchanged. A complete unmasked application-marker prefix still fails validation; this step does not relax the existing evidence gates.
