# Complete Codex workflow evaluation

`evaluate_workflows.py` executes the seven cases in `evaluation-cases.json` in fresh workspaces. The default is three repetitions for each of baseline skill 1.1.29 and candidate 1.2.0: 42 sequential agent runs. Select the same reviewed MCP package, frozen corpus, explicit CLI, Python, and PowerShell for both arms. It reads the configured model and effort once, or accepts explicit values; it never changes models or automatically retries a failed run.

Use absolute paths and a new output directory:

```powershell
& '<python.exe>' -B '<repository>/tests/evaluate_workflows.py' --skill-root '<candidate-skill>' --baseline-skill-root '<baseline-skill>' --mcp-package-root '<reviewed-portable-mcp>' --codex-path '<supported-codex.exe>' --powershell '<pwsh.exe>' --output '<new-evidence-directory>' --model gpt-6-astra --reasoning-effort xhigh
```

The CLI must support JSONL traces, structured final output, ephemeral sessions, and workspace-write sandboxing. Its version and executable hash are frozen in the result. Each run has a ten-minute maximum deadline and owned-descendant cleanup through a Windows job object. No native MetaEditor/MT5 or trading execution is permitted. Include-impact compilation uses synthetic executables whose metadata identifies them as test doubles. Isolated test preparation uses an explicitly prompted bounded format: a single `ClampCount` definition with a return expression, plus `#include "Calculation.mqh"` and `void OnStart()` containing exactly six sequential `if (ClampCount(n,maximum) != expected) Print("FAIL:case label");` assertions. Integers and expected values must match the independent specification; order may differ. Comments and `#property strict` are allowed. Commented calls, incorrect expected values, unused functions, extra control flow, and additional executable code fail scoring. The bounded integer-expression interpreter and assertion checks establish preparation evidence; they do not execute MQL5 behavior or validate arbitrary MQL5 test formats.

The supported processing bound is 16 MiB of combined retained stdout and stderr. The runner checks this during execution and again after owned-process cleanup; an output burst may overshoot the bound in retained evidence, but it cannot be scored as completed. Oversized trace evidence is retained and not parsed.

The bounded calculation check permits only integer-valued constants, the ASCII identifiers `n` and `maximum`, unary minus, and two-argument `MathMin`/`MathMax` calls after the complete definition and comment lexer checks. Physical expression whitespace and comments may separate names from parentheses. Non-ASCII identifier lookalikes fail before Python can normalize them. Assertion integers use ASCII decimal digits; Unicode inside comments and `Print` strings remains permitted. These checks cover the specified preparation format and six values, not complete native MQL5 syntax or every numerical-literal spelling. A native compiler remains responsible for build validity.

The JSONL reader recognizes physical LF, CRLF, and CR record endings. Valid Unicode separators inside JSON strings remain part of the event, including command output, and do not create extra trace records.

Only the selected staged skill and reviewed MCP are configured. Desktop IPC and originator environment variables are removed. A temporary credential store outside fixtures and retained evidence supplies normal CLI authentication and is cleaned afterward. Credentials are never copied into workspaces or evaluation artifacts. Windows execution uses the native unelevated workspace sandbox with a run-local TEMP/TMP directory; unavailable sandbox execution is failed evidence, not a reason to remove sandboxing. Synthetic executable bytes are compiled once and reused identically for both arms. Absolute path bindings differ with each fresh workspace and are retained explicitly.

Artifacts and structured conclusions determine correctness. Traces record resource selection, completed command counts, and observable forbidden execution/publication attempts. A terminal executable reference is exempt only when the entire command consists of recognized static file or metadata reads. Mixed commands, pipelines, call operators, shell wrappers, and uncertain reference contexts fail this bounded scoring check; a word such as `profile` elsewhere never authorizes execution. This check does not parse every shell language or prove the absence of indirect execution, and the workspace sandbox remains required. Malformed events, item roots, item types, command values, and usage values remain failed evidence; valid events can still supply available metrics without crashing score publication. Measurements retain elapsed time, console/artifact bytes, available token usage, repeated identical commands, and runner retry count zero. Semantic agent retries are explicitly unavailable as a stable metric. Retain failed and timed-out runs. Do not label baseline failures as candidate successes, infer native behavior from test doubles, or claim a general percentage improvement from this small sample.

Named editor and compiler-helper attempts fail in cases that forbid compilation, even when a failed attempt produces no EX5 or receipt. Only include-impact permits its supplied project compilation workflow and prepared synthetic editor path. Project compilation requires one literal, unabbreviated `-ProfilePath` resolving to the prepared `inputs/project/profile.json`; missing, foreign, dynamic, or duplicate selectors fail scoring. Direct compiler-helper use must explicitly select that prepared editor with a literal `-MetaEditorPath`; default editor discovery and dynamic selectors fail scoring. Project and batch validation defaults remain allowed; explicit tester workflows, batch execution, and uncertain dynamic/abbreviated project actions fail scoring. The same bounded static-read exemption permits inspecting compiler/tester scripts and executable metadata. These are checks of recorded named actions, not proof about arbitrary indirect shell execution.

Include-impact success additionally requires a completed, exit-zero command trace for the selected staged `Invoke-Mql5Project.ps1`, its literal prepared profile and `Compile` action, and the emitted `MQL5_COMPILE_RECEIPT` paths. The observer recognizes a whole direct literal invocation or an explicit PowerShell `-File` invocation; a single literal PowerShell `-Command` payload may contain the direct call. Host-wrapped invocations must select the reviewed `--powershell` executable whose path and hash are recorded; a matching basename in another directory is insufficient. Comments, quoted output, inert assignments, foreign scripts and appended execution are not compilation evidence. The internal development helper `Verify-WorkflowReceipts.ps1` uses the reviewed candidate's original receipt and path-integrity helpers outside the writable workspace to verify both selected sources, EX5 files and retained logs. Its identity is recorded with the evaluator. Minimal success claims, missing or changed source/artifact/log commitments, wrong entrypoints and receipt paths not bound to completed output fail scoring. Receipts contain hash commitments, not signatures, and this evidence establishes synthetic workflow execution rather than native MQL5 behavior.

Each arm records its own complete selected staged skill inventory before and after the agent task. Changed or missing original resources and added files, including executable bytecode caches, fail scoring. Evaluation children inherit `PYTHONDONTWRITEBYTECODE=1`, and prompts require Python `-B` for toolkit commands; no global environment settings change. Any pre-existing copied caches belong to that arm's protected initial inventory. This prevents a changed staged wrapper from passing as the selected workflow while ordinary imports leave the selected resources unchanged. These comparisons establish recorded before/after byte identity; they do not prove the absence of transient changes or form a security boundary.

`test_workflow_evaluator.py` validates scoring and process cleanup with synthetic traces/processes without credentials. Automatic CI runs those deterministic tests. `workflow-evaluation.yml` is manually dispatched, with one job per case. It requires a reviewed MCP commit and successful release-validation run retaining its package. Missing `OPENAI_API_KEY` produces an actionable `unavailable` artifact; the mandatory live evaluation gate runs locally. Private counterpart artifacts additionally need `MQL5_PEER_ACTIONS_TOKEN` with read-only Actions access. Job-local credentials are excluded from uploaded evidence.
